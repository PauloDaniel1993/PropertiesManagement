# Parallel Feature Development

This repository uses Git Flow with one feature branch per completed capability. To increase safe parallel work, module teams should own files inside their module folders and avoid shared root files whenever possible.

## Branches

- Branch from `develop`.
- Use `feature/<module-or-capability>`.
- Open one pull request per completed feature or coherent capability.
- Keep OpenSpec task updates in the integration branch or have one owner update `openspec/changes/**/tasks.md`.

## Backend API Modules

Feature endpoints should live under `src/Alsappan.Api/<Feature>/`.

To register endpoints, add a small class beside the endpoint mapper:

```csharp
internal sealed class DocumentEndpointModule : IApiEndpointModule
{
  public int Order => 400;

  public void MapEndpoints(RouteGroupBuilder v1) => v1.MapDocumentEndpoints();
}
```

`Program.cs` discovers endpoint modules automatically. New feature branches should not edit `Program.cs` just to add routes.

## Infrastructure Modules

Feature infrastructure should live under `src/Alsappan.Infrastructure/<Feature>/`.

To register repositories and services, add a module class:

```csharp
internal sealed class DocumentInfrastructureModule : IInfrastructureModule
{
  public int Order => 400;

  public void AddServices(IServiceCollection services)
  {
    services.AddScoped<IDocumentRepository, EfDocumentRepository>();
    services.AddScoped<IDocumentService, DocumentService>();
  }
}
```

`AddInfrastructure()` discovers these modules automatically. New feature branches should not edit `DependencyInjection.cs` for ordinary module registrations.

## Frontend Module Pages

Feature UI should live under `src/Alsappan.Web/src/features/<feature>/`.

To replace a placeholder route with an implemented page, add `modulePageRoute.tsx`:

```tsx
import type { ModulePageRouteContribution } from '../../routes/modulePageRouteRegistry'
import { DocumentsListPage } from './DocumentsListPage'

export const modulePageRoute = {
  Component: DocumentsListPage,
  routeId: 'documents',
} satisfies ModulePageRouteContribution
```

`AppRoutes.tsx` discovers page contributions automatically. New feature branches should not edit `AppRoutes.tsx` just to add a module page.

## Shared-File Rules

- One owner per shared file.
- EF migrations and `AlsappanDbContextModelSnapshot.cs` should be serialized or regenerated by the integrator before PR creation.
- Menu contract changes remain centralized because they define the product navigation surface.
- OpenSpec task checkboxes should be updated by the PR owner only for tasks completed in that PR.
